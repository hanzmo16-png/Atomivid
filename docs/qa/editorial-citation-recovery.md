# Editorial citation recovery

A completed, stored critic response may abbreviate literal excerpts with an ellipsis or return an unusable evidence reference. These are completed calls, not uncertain provider outcomes.

The validator expands only unambiguous ordered excerpts in the same beat. Every fragment must contain at least three words and occur exactly once. The resulting citation is the full original span, including omitted qualifications. Missing words, reversed/ambiguous fragments and invented content are not accepted.

If citations remain invalid, preparation can request exactly one citation-only correction across both narrative drafts. It returns replacements for the invalid paths; no indices, findings, severity, judgments, narration or source assignments can change. All citations and all existing editorial gates are then validated again. Empty, incomplete, invented, cross-beat or uncertain corrections stop preparation. SDK retries remain zero.

The extra correction has a 2,000-token output cap and passes through the existing reservation, supplier capacity and spending gates. It has its own deterministic paid-operation key and stored raw response. A resumed worker reuses completed research, narration, critique and correction results. No media generation is started by this change.

Original research/writer/critic request bodies are unchanged. No existing job is restarted by deployment. The read-only diagnostic emits structural statistics only and has no provider credentials or write operations.

Validation: TypeScript, editorial/citation regression tests, and free inspection of stored responses. Live correction quality remains subject to the same evidence gate; synthetic tests do not prove live editorial judgment.
